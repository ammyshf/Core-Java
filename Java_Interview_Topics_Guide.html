OOP Fundamentals
Encapsulation · Inheritance · Polymorphism · Abstraction
The bedrock of every Java interview. Interviewers test OOP not just for definitions — they want to see you apply these principles to real design problems. Expect questions like "how would you design a parking lot?" or "explain method overloading vs overriding with an example."
🔥 Highest Priority
Encapsulation
Access Modifiers Data Hiding
Bundling data with methods that operate on it, and restricting direct access via access modifiers (private, protected, public).
private / protected / public / package-private
Getter & setter patterns, bean conventions
Immutable classes (final fields + no setters)
Interview Frequency
🔥 Highest Priority
Inheritance & Polymorphism
extends Overriding Dynamic Dispatch
IS-A relationship via extends and implements. Polymorphism enables a single interface to represent different underlying types — both compile-time (overloading) and runtime (overriding).
Method overloading vs. overriding (rules & differences)
Covariant return types, super keyword
Why Java doesn't support multiple class inheritance
Dynamic method dispatch & vtable concept
Interview Frequency
🔥 Highest Priority
Abstraction
abstract class interface default methods
Hiding complexity behind a contract. The classic interview question: abstract class vs. interface — know every difference cold.
Abstract class: partial implementation, constructors allowed
Interface: default/static methods since Java 8
When to choose interface vs abstract class
Marker interfaces (Serializable, Cloneable)
Interview Frequency
🔥 Highest Priority
Object Class & Core Contracts
equals/hashCode toString Comparable
Every class inherits Object. Interviewers constantly probe equals() & hashCode() contracts — violating them breaks Collections.
equals() & hashCode() contract (reflexive, symmetric, transitive)
Comparable vs. Comparator
clone() — deep vs. shallow copy
finalize() — why it's deprecated
Interview Frequency
2
Collections Framework
List · Set · Map · Queue · Internal Implementations
Collections is the most tested area in Java interviews. You will be asked to compare data structures, explain internal workings (especially HashMap internals), and pick the right structure for a scenario. Leetcode-style DSA problems also heavily rely on this knowledge.
🔥 Highest Priority
HashMap & ConcurrentHashMap
Hashing Buckets Thread Safety
The #1 most asked data structure. Know the internal array-of-buckets structure, hash collision handling (chaining → treeification in Java 8), load factor, resize, and the difference from ConcurrentHashMap.
Initial capacity (16), load factor (0.75), resize at 75% full
Java 8: bucket list → red-black tree at threshold 8
ConcurrentHashMap: segment locks → CAS + synchronized buckets
LinkedHashMap (insertion order), TreeMap (sorted)
Why HashMap is NOT thread-safe (race on resize)
Interview Frequency
🔥 Highest Priority
List Implementations
ArrayList LinkedList Vector
Know the time complexities cold. ArrayList is O(1) random access but O(n) insert/delete. LinkedList is O(1) insert/delete at ends but O(n) access. Always explain why.
ArrayList internal array — resize by 50% growth
LinkedList — doubly linked, also implements Deque
ArrayList vs Vector (synchronization overhead)
CopyOnWriteArrayList — safe iteration under writes
Interview Frequency
🔥 Highest Priority
Set Implementations
HashSet TreeSet LinkedHashSet
HashSet internally uses HashMap (the value is a dummy Object). TreeSet uses a Red-Black Tree — O(log n) ops but always sorted. Key question: how does HashSet determine uniqueness?
HashSet = HashMap with dummy value — equals() + hashCode() for uniqueness
TreeSet = TreeMap — natural order or custom Comparator
EnumSet — highly efficient bit-vector backed set
Interview Frequency
🔥 Highest Priority
Queue, Deque & PriorityQueue
Queue BlockingQueue Min/Max Heap
PriorityQueue backs every Dijkstra / BFS / K-largest interview problem. BlockingQueue is the foundation of the producer-consumer pattern tested in concurrency questions.
PriorityQueue — min-heap by default; use Comparator for max-heap
ArrayDeque — faster than LinkedList for stack/queue usage
BlockingQueue, LinkedBlockingQueue, ArrayBlockingQueue
Interview Frequency
⚡
Key Interview Question: Collections Complexity Cheat Sheet
Always know: ArrayList — O(1) get, O(n) add(0); LinkedList — O(1) add/remove at ends, O(n) get; HashMap/HashSet — O(1) avg, O(n) worst; TreeMap/TreeSet — O(log n) all ops; PriorityQueue — O(log n) add/poll, O(1) peek.

Multithreading & Concurrency
Thread Lifecycle · Synchronization · Locks · Concurrent Utilities
This is a senior interview differentiator. Even entry-level roles increasingly ask about threads. Interviewers test whether you understand race conditions, deadlocks, and thread-safe patterns — not just how to create a thread.
🔥 Highest Priority
Thread Lifecycle & Creation
Thread Runnable Callable
Know all 6 thread states (NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED) and every state transition. Know the difference between Thread subclassing vs. Runnable vs. Callable.
start() vs run() — crucial distinction
sleep() vs wait() — sleep doesn't release lock
join(), interrupt(), daemon threads
Thread pool via ExecutorService, Executors factory
Interview Frequency
🔥 Highest Priority
synchronized, volatile & Locks
synchronized volatile ReentrantLock
synchronized provides mutual exclusion + visibility. volatile provides only visibility (no atomicity). Know when each is needed — this is a constant interview trap.
Monitor lock — object lock vs. class lock
volatile — prevents caching, ensures happens-before
ReentrantLock — tryLock, lockInterruptibly, fairness
ReadWriteLock for read-heavy scenarios
Interview Frequency
🔥 Highest Priority
Deadlock, Race Condition & Livelock
Deadlock Race Condition Starvation
Interviewers love asking you to identify and fix a deadlock in code. Know the four Coffman conditions for deadlock and strategies to prevent/detect it.
4 Coffman conditions: mutual exclusion, hold & wait, no preemption, circular wait
Prevention: consistent lock ordering, tryLock with timeout
Race condition: check-then-act & read-modify-write patterns
Interview Frequency
🔥 Highest Priority
java.util.concurrent Utilities
CountDownLatch Semaphore Future
The java.util.concurrent package is extensively used in production and increasingly tested. CompletableFuture is especially hot in modern interviews.
CountDownLatch — wait for N events; not reusable
CyclicBarrier — all threads wait at a barrier; reusable
Semaphore — controls access to N permits (rate limiting)
CompletableFuture — async pipeline with thenApply/thenCompose
AtomicInteger, AtomicReference — lock-free CAS operations
Interview Frequency

Java Memory Model & Garbage Collection
Heap · Stack · GC Algorithms · Memory Leaks
Understanding the JVM memory model is what separates good Java developers from great ones. Questions about memory leaks, GC tuning, and OutOfMemoryError are common in senior interviews. Even junior interviews ask about stack vs heap.
🔥 Highest Priority
Heap vs. Stack Memory
Heap Stack Method Area
Stack: thread-local, holds local vars & method frames, auto-managed. Heap: shared across threads, holds objects, GC-managed. Interviewers test where objects and primitives live.
Heap: Young Gen (Eden + Survivor), Old Gen, Metaspace
Stack overflow vs. heap OutOfMemoryError
String Pool (part of Heap since Java 7)
Interview Frequency
🔥 Highest Priority
Garbage Collection Algorithms
Mark & Sweep G1GC ZGC
Know the generational hypothesis — most objects die young. Understand minor GC vs. major GC vs. full GC and when each triggers.
Serial, Parallel, CMS, G1GC, ZGC, Shenandoah
G1GC: default since Java 9 — region-based, low pause
Stop-the-world pauses and their impact
GC roots: thread stacks, static fields, JNI refs
Interview Frequency
🔥 Highest Priority
Memory Leaks in Java
Memory Leak WeakReference ThreadLocal
Java can still have memory leaks even with GC. The most common causes: unclosed streams, static collections growing unbounded, ThreadLocal not removed, listeners not deregistered.
Static fields holding references to large objects
ThreadLocal leak in thread-pool environments
WeakReference, SoftReference, PhantomReference
Diagnosing with VisualVM / jmap / heap dumps
Interview Frequency
🔥 Highest Priority
Java Memory Model (JMM)
happens-before Visibility Atomicity
The JMM defines when one thread's writes are guaranteed visible to another. This underpins all concurrency correctness. Essential for senior interviews.
happens-before guarantee: synchronization, volatile, Thread.start/join
Instruction reordering by CPU / JIT — why volatile matters
Double-checked locking + volatile fix for Singleton
Interview Frequency
⚡ Tier 2
High Importance — Asked in most mid-level to senior interviews. These topics show depth of Java knowledge beyond basic OOP. Expect follow-up questions if you mention them.

Java 8+ Features
Streams · Lambdas · Optional · Functional Interfaces
Java 8 transformed the language. Almost every modern Java project uses Streams and Lambdas, so these are now baseline expectations. Be ready to write stream pipelines on a whiteboard.
⚡ High Priority
Lambda Expressions & Functional Interfaces
Lambda @FunctionalInterface
Lambdas are anonymous functions enabling functional-style programming. Functional interfaces (exactly 1 abstract method) are their type. Know the 4 core built-in functional interfaces.
Predicate<T> — T → boolean (test/filter)
Function<T,R> — T → R (transform/map)
Consumer<T> — T → void (side effects)
Supplier<T> — () → T (factory/lazy init)
Method references: Class::method, instance::method
Interview Frequency
⚡ High Priority
Stream API
Stream Lazy Evaluation Parallel Streams
Declarative data processing pipeline. Streams are lazy — intermediate operations only run when a terminal operation is invoked. Know the difference between intermediate and terminal ops.
Intermediate: filter, map, flatMap, distinct, sorted, peek
Terminal: collect, forEach, reduce, count, findFirst, anyMatch
Collectors.groupingBy, partitioningBy, joining, toMap
Parallel streams — ForkJoinPool, when to use (CPU-bound, stateless)
Interview Frequency
⚡ High Priority
Optional<T>
Null Safety Optional
A container that may or may not hold a value, designed to eliminate NullPointerException. Know the API and common anti-patterns (like Optional.get() without check).
of(), ofNullable(), empty() — creation methods
isPresent() vs. ifPresent(), orElse vs. orElseGet
map(), flatMap(), filter() on Optional
Anti-pattern: using as method parameter type or in collections
Interview Frequency
⚡ High Priority
Default & Static Interface Methods
default static Diamond Problem
Java 8 added default methods to interfaces, enabling backward-compatible API evolution. Understand the diamond problem resolution rules.
default methods — class override wins over interface default
Diamond conflict resolution: class > interface, more specific > less specific
static methods in interface — not inherited
Interview Frequency

Exception Handling
Checked · Unchecked · try-with-resources · Custom Exceptions
Exception handling is asked in almost every Java interview. Questions range from the class hierarchy to tricky scenarios like returning from a finally block or catching exceptions in lambdas.
⚡ High Priority
Exception Hierarchy
Throwable Checked Unchecked
Throwable → Error | Exception. Error is non-recoverable (OOM, StackOverflow). Checked exceptions must be declared/caught (IOException, SQLException). Unchecked (RuntimeException) — optional handling.
Checked: IOException, SQLException, ClassNotFoundException
Unchecked: NullPointerException, ArrayIndexOutOfBoundsException, IllegalArgumentException
When to use checked vs. unchecked (design decision)
Interview Frequency
⚡ High Priority
try-with-resources & finally
AutoCloseable finally Suppressed
Java 7's try-with-resources automatically closes AutoCloseable resources. The tricky interview question: what happens when both the try block and close() throw exceptions?
Suppressed exceptions via Throwable.getSuppressed()
finally always executes (except System.exit() / JVM crash)
Return in finally overrides return in try — interview trap!
Interview Frequency
7
String Internals
Immutability · String Pool · StringBuilder · Performance
Strings are the most commonly used class in Java and appear in almost every interview — both as direct questions about internals and as DSA problems (palindromes, anagrams, etc.).
⚡ High Priority
Immutability & String Pool
Immutable intern() == vs equals()
String is immutable by design — thread-safe, cacheable hashCode, security benefits. The String Pool (interning) reuses literal instances. == vs equals() is a classic trap.
"hello" == "hello" → true (pool); new String("hello") == "hello" → false
intern() — move to pool; use sparingly (PermGen/Metaspace pressure)
Why immutable: security (ClassLoader, network), hashCode caching, thread safety
Interview Frequency
⚡ High Priority
String vs StringBuilder vs StringBuffer
Performance Mutable Thread Safe
String concatenation in a loop creates O(n²) garbage. StringBuilder is O(n) and should be used for mutable string building. StringBuffer is synchronized — use only when sharing across threads (rare).
Java 9+ compiles "a" + b into StringConcatFactory (not always StringBuilder)
StringBuffer: synchronized, legacy, avoid unless truly needed
charAt, indexOf, substring, replace — all return new String
Interview Frequency

Generics & Type System
Type Parameters · Wildcards · Type Erasure · Bounded Types
Generics enable type-safe, reusable code. Understanding type erasure and wildcards is critical for working with Collections and designing APIs — and is a common source of interview questions about why certain operations don't compile.
⚡ High Priority
Generic Classes & Methods
<T> bounded PECS
Generics provide compile-time type safety. Know the PECS principle: Producer Extends, Consumer Super — the rule for using wildcards with Collections correctly.
Upper bounded: <T extends Number> — read from it
Lower bounded: <T super Integer> — write to it
Wildcard <?> — unknown type, read-only
Type erasure — generics exist only at compile time; <T> becomes Object at runtime
Interview Frequency
⚡ High Priority
Enums, Records & Sealed Classes
enum record sealed
Enums are type-safe constants with full class capabilities. Records (Java 16) are immutable data carriers. Sealed classes (Java 17) restrict the class hierarchy — great for modeling domain types.
Enum: values(), ordinal(), name(), valueOf(); can have fields & methods
EnumMap and EnumSet — highly efficient for enum-keyed data
Record: auto-generates constructor, equals, hashCode, toString
Interview Frequency

Medium Importance — Expected at mid-senior level; differentiates strong candidates. Deep knowledge here signals genuine engineering maturity.

SOLID Principles
SRP · OCP · LSP · ISP · DIP
SOLID principles are the foundation of maintainable, scalable object-oriented design. Interviewers at all levels ask about them — often asking you to identify which principle a bad code snippet violates.
Principle One-line Rule Common Interview Ask
S — Single ResponsibilityA class should have one reason to changeIdentify what "responsibility" a god-class should split into
O — Open/ClosedOpen for extension, closed for modificationHow do you add a new payment method without modifying existing code?
L — Liskov SubstitutionSubtypes must be substitutable for their base typesWhy does Square extends Rectangle violate LSP?
I — Interface SegregationClients should not depend on interfaces they don't useSplit a fat interface into role-specific ones
D — Dependency InversionDepend on abstractions, not concretionsHow does Spring DI implement this principle?

JVM Internals
ClassLoader · JIT · Bytecode · Runtime Data Areas
JVM internals are expected knowledge at senior level. Understanding how Java bytecode is loaded, verified, and compiled by JIT helps you reason about performance, startup time, and ClassLoader-based frameworks (Spring, OSGi).
🔵 Medium-High Priority
ClassLoader Subsystem
Bootstrap Platform Application
ClassLoaders follow a parent-delegation model — before loading a class, a loader asks its parent first. This prevents malicious code from substituting core Java classes.
Bootstrap (JVM core) → Platform → Application → Custom
Class loading phases: Loading → Linking (Verify/Prepare/Resolve) → Initialization
Hot reloading, OSGi, and custom ClassLoaders
Interview Frequency
🔵 Medium-High Priority
JIT Compiler & Bytecode
JIT Bytecode AOT
JVM interprets bytecode initially, then JIT-compiles hot paths to native code. HotSpot uses C1 (client/fast compile) and C2 (server/optimizing) compilers in tiered compilation.
Tiered compilation: interpreted → C1 → C2
Inlining, escape analysis, dead code elimination
AOT (GraalVM native-image) — no JIT, instant startup
Interview Frequency

I/O, NIO & Serialization
Streams · Channels · Buffers · Serializable
I/O is fundamental to any real application. Java NIO's non-blocking I/O via Selectors and Channels is the basis for high-performance servers (Netty, etc.). Serialization questions arise in distributed systems context.
🔵 Medium-High Priority
Java I/O Streams
InputStream OutputStream Reader/Writer
Java I/O is built on the Decorator pattern — wrap streams to add buffering, compression, encryption, etc. Always close streams (use try-with-resources).
Byte streams (InputStream/OutputStream) vs. character streams (Reader/Writer)
BufferedReader/Writer, PrintWriter for text
Files, Paths, FileChannel (NIO) for modern file I/O
Interview Frequency
🔵 Medium-High Priority
Serialization & Deserialization
Serializable serialVersionUID Externalizable
Java Serialization converts objects to bytes. serialVersionUID controls version compatibility. Know the security risks — deserialization of untrusted data is a major vulnerability vector.
transient fields — excluded from serialization
readObject/writeObject custom serialization hooks
Externalizable — full manual control, more performant
Security: gadget chains, use of ObjectInputFilter
Interview Frequency

Good-to-Know — Distinguish top candidates at senior/staff level. Knowing these topics shows broad Java ecosystem awareness and production readiness.

Reflection & Annotations
java.lang.reflect · @Annotation · Runtime Metadata
Reflection powers frameworks like Spring, Hibernate, and JUnit. While you rarely write reflection code directly, understanding it explains how these frameworks work. Annotations are ubiquitous in modern Java code.
🟢 Good to Know
Reflection API
Class<?> Method Field
Inspect and manipulate classes, methods, and fields at runtime without compile-time knowledge. Performance cost: reflection bypasses JIT inlining optimizations.
Class.forName(), getMethod(), getDeclaredField()
invoke(), setAccessible(true) — module access warnings in Java 9+
Dynamic proxies (java.lang.reflect.Proxy) — Spring AOP
Interview Frequency
🟢 Good to Know
Annotation Processing
@Retention @Target APT
Annotations are metadata markers. Retention controls when they're available (SOURCE/CLASS/RUNTIME). Spring, JPA, and JUnit rely entirely on runtime annotations.
@Retention(RUNTIME) — visible via reflection
@Target — restrict where annotation can appear
Compile-time annotation processors (Lombok, MapStruct)
Interview Frequency

JDBC & Persistence
JDBC · Connection Pools · JPA / Hibernate
Database connectivity is essential for backend roles. While most modern apps use JPA/Hibernate, interviewers often ask JDBC questions to test fundamentals. N+1 query problem and transaction management are hot topics.
🟢 Good to Know
JDBC Core
Connection PreparedStatement SQL Injection
Always use PreparedStatement over Statement to prevent SQL injection. ConnectionPool (HikariCP) avoids expensive connection creation per request.
DriverManager vs DataSource / connection pool
Transaction management: commit, rollback, Savepoints
ResultSet types: forward-only, scrollable, updatable
Interview Frequency
🟢 Good to Know
JPA & Hibernate
ORM N+1 Problem Lazy Loading
JPA is the spec; Hibernate is the most popular implementation. N+1 query problem is the #1 performance issue and an extremely common interview question for any Spring/JPA role.
Entity states: transient, persistent, detached, removed
N+1 problem: fix with JOIN FETCH or @BatchSize
First-level cache (session) vs second-level cache (EhCache)
Optimistic vs pessimistic locking (@Version)
Interview Frequency

Testing & Build Tools
JUnit · Mockito · Maven · Gradle
Professional Java development requires unit testing and build automation. Modern interviews increasingly ask about TDD and test design. Knowledge of Maven/Gradle dependency management is assumed for any Java role.
🟢 Good to Know
JUnit 5 & Mockito
@Test @Mock TDD
JUnit 5 introduced the Jupiter API with a more flexible extension model. Mockito is essential for isolating units under test by mocking dependencies.
@Test, @BeforeEach, @AfterEach, @ParameterizedTest
Assertions.assertEquals, assertThrows, assertAll
Mockito: @Mock, @InjectMocks, when().thenReturn(), verify()
Test doubles: mock vs stub vs spy vs fake
Interview Frequency
🟢 Good to Know
Maven & Gradle
pom.xml build.gradle Lifecycle
Build tools automate compilation, testing, and packaging. Know the Maven lifecycle phases and how to manage dependency scopes (compile, test, provided, runtime).
Maven phases: validate → compile → test → package → install → deploy
Dependency scopes and transitive dependency management
Gradle: build.gradle.kts (Kotlin DSL), task graph, incremental builds
